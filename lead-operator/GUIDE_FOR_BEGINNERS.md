# 📘 Руководство для новичка: Как работать с ИИ-оператором лидов

Привет! Это пошаговое руководство поможет тебе разобраться с проектом, даже если ты раньше не работал с Python или Docker.

---

## 🎯 Что мы построили

Мы создали **ИИ-оператора лидов** — бота, который:
- Отвечает на сообщения в Telegram и WhatsApp за секунды
- Квалифицирует клиентов (услуга, бюджет, срочность)
- Записывает на удобное время
- Уведомляет владельца о горячих лидах

## 🚀 Быстрый старт

### Шаг 1: Проверка тестов

Прежде чем запускать приложение, убедись, что все тесты проходят:

```bash
cd /workspace/lead-operator
python -m pytest tests/ -v
```

✅ **Ожидаемый результат:** `15 passed`

Если видишь `FAILED` — сообщи мне, будем разбираться!

---

### Шаг 2: Настройка окружения

#### 2.1. Создай файл `.env`

В проекте уже есть файл `.env` с тестовыми значениями. Для реальной работы нужно создать свой:

```bash
cp .env.example .env.local
```

#### 2.2. Заполни ключи в `.env.local`

Открой файл `.env.local` и заполни:

```env
# Telegram Bot Token (получи у @BotFather)
TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz

# WhatsApp Green API (регистрация на wa.green-api.com)
GREEN_API_ID=1101234567
GREEN_API_TOKEN=abcdef1234567890abcdef1234567890abcdef1234567890abcdef1234567890

# DashScope API Key (регистрация на dashscope.aliyun.com)
DASHSCOPE_API_KEY=sk-abcdef1234567890

# База данных (для Docker оставь как есть)
DATABASE_URL=postgresql://postgres:postgres@db:5432/lead_operator

# Redis (для Docker оставь как есть)
REDIS_URL=redis://redis:6379/0

# Твой Telegram ID (куда слать уведомления)
# Узнай у @userinfobot
OWNER_TELEGRAM_ID=123456789

# Режим работы
APP_ENV=production
LOG_LEVEL=INFO
```

📌 **Как получить ключи:**

| Ключ | Где получить | Время |
|------|--------------|-------|
| `TELEGRAM_BOT_TOKEN` | Напиши @BotFather в Telegram → `/newbot` | 2 мин |
| `GREEN_API_ID`, `GREEN_API_TOKEN` | Регистрация на [wa.green-api.com](https://wa.green-api.com) | 5 мин |
| `DASHSCOPE_API_KEY` | Регистрация на [dashscope.aliyun.com](https://dashscope.aliyun.com) | 3 мин |
| `OWNER_TELEGRAM_ID` | Напиши @userinfobot в Telegram | 10 сек |

### Шаг 3: Запуск через Docker

#### 3.1. Установи Docker (если нет)

**Windows/Mac:** Скачай с [docker.com](https://www.docker.com/products/docker-desktop)

**Linux (Ubuntu):**
```bash
sudo apt update
sudo apt install docker.io docker-compose
sudo usermod -aG docker $USER
# Перелогинься после этой команды
```

#### 3.2. Запусти контейнеры

```bash
cd /workspace/lead-operator
docker-compose up -d
```

🕐 **Подожди 30 секунд** пока поднимутся базы данных.

#### 3.3. Проверь, что всё работает

```bash
docker-compose ps
```

✅ **Ожидаемый результат:**
```
NAME                    STATUS
lead-operator-app       Up
lead-operator-db        Up
lead-operator-redis     Up
```

#### 3.4. Посмотри логи

```bash
docker-compose logs -f app
```

Нажми `Ctrl+C` чтобы выйти из режима логов.

## 🧪 Тестирование работы

### Тест 1: Проверка Telegram-бота

1. **Найди своего бота** в Telegram по имени, которое ты дал при создании
2. **Напиши ему:** `Привет, хочу записаться на стрижку`
3. **Ожидай ответ** (должен прийти через 1-5 секунд)

📝 **Что должно произойти:**
- Бот представится ИИ-ассистентом
- Задаст уточняющие вопросы (когда удобно, какой бюджет)
- В конце предложит свободные слоты

### Тест 2: Проверка квалификации

Попробуй разные сценарии:

| Сценарий | Что написать | Ожидаемый результат |
|----------|--------------|---------------------|
| **Запись** | "Хочу записаться на маникюр завтра" | Бот предложит слоты |
| **Негатив** | "Ужасный сервис, верните деньги!" | Эскалация владельцу |
| **Хочу человека** | "Соедините с оператором" | Передача человеку |
| **Вне FAQ** | "Какой у вас курс доллара?" (спроси 2 раза) | Эскалация после 2-го раза |
| **Крупный бюджет** | "Нужно обслуживание за 50000 руб" | Эскалация (крупная сделка) |

### Тест 3: Проверка уведомлений

Когда сработает эскалация (негатив, крупный бюджет, запрос человека):

1. **Проверь свой Telegram** (OWNER_TELEGRAM_ID)

## 🛠️ Частые проблемы и решения

### ❌ Ошибка: "Connection refused" к базе данных

**Причина:** База ещё не успела запуститься.

**Решение:**
```bash
docker-compose down
docker-compose up -d
# Подожди 30 секунд
docker-compose logs app
```

---

### ❌ Ошибка: "Invalid bot token"

**Причина:** Неправильный токен в `.env`.

**Решение:**
1. Проверь токен в @BotFather
2. Обновить `.env`
3. Перезапусти: `docker-compose restart app`

---

### ❌ Бот не отвечает

**Чеклист:**
1. ✅ Вебхук настроен? (см. ниже)
2. ✅ Бот не заблокирован пользователем?
3. ✅ Есть ли логи ошибки? (`docker-compose logs app`)

---

### ❌ Тесты не проходят

**Решение:**
```bash
# Очисти кэш pytest
rm -rf .pytest_cache __pycache__ tests/__pycache__

# Запусти заново
python -m pytest tests/ -v
```

Если всё ещё失败 — пришли мне вывод тестов.

## 🔗 Настройка вебхуков

### Telegram

Вебхук нужно настроить один раз:

```bash
curl -X POST "https://api.telegram.org/bot<YOUR_BOT_TOKEN>/setWebhook" \
  -d "url=https://your-server.com/api/webhook/telegram"
```

Для локальной тестировки используй **ngrok**:

```bash
# Установи ngrok
# Скачай с https://ngrok.com

# Запусти
ngrok http 8000

# Скопируй URL (например, https://abc123.ngrok.io)
# И настрой вебхук:
curl -X POST "https://api.telegram.org/bot<YOUR_BOT_TOKEN>/setWebhook" \
  -d "url=https://abc123.ngrok.io/api/webhook/telegram"
```

### WhatsApp (Green API)

1. Зайди в личный кабинет Green API
2. Перейди в настройки экземпляра
3. Укажи webhook URL: `https://your-server.com/api/webhook/whatsapp`

## 📊 Мониторинг метрик

### Критерии приёмки (из ТЗ)

| Метрика | Требование | Как проверить |
|---------|------------|---------------|
| Ответ лиду | < 5 секунд | Засекай время от отправки до ответа |
| Квалификация | ≥3 поля у 80% диалогов | Смотри в БД: `SELECT qualification FROM leads` |
| Запись на слот | Сохраняется и подтверждается | Проверяй таблицу `slot_bookings` |
| Уведомление владельцу | ≤ 1 минуты | Засекай время от эскалации до уведомления |
| Галлюцинации | 0 в тестовых сценариях | Прогони тестовые сценарии |

## 💡 Советы для эффективной работы

1. **Маленькие шаги:** Делай по одному изменению за раз
2. **Тестируй сразу:** После каждого изменения запускай тесты
3. **Смотри логи:** 90% проблем видны в логах
4. **Не бойся спрашивать:** Если что-то непонятно — спроси меня!
